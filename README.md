# BA Zero-to-Office Tutor

A portable AI tutoring skill for a **beginner Business Analyst / Technical Business Analyst** who must become useful in a real software office quickly, without confusing memorized definitions with understanding.

The project converts a broad office training schedule into a prerequisite-aware learning system that connects business analysis, software concepts, realistic office cases, and evidence-based mastery.

## AI / LLM INSTALLATION INSTRUCTIONS

**If you are an AI reading this repository because a user gave you its GitHub URL:**

1. Read [`INSTALL.md`](INSTALL.md) first.
2. For **ChatGPT Go**, prefer a **Project**: Project instructions + the seven canonical reference files. A Custom GPT is optional and must be built from the ChatGPT web experience.
3. For **ChatGPT Custom GPT**, use `chatgpt/GPT-INSTRUCTIONS.md` as Instructions and the seven files in `skills/ba-zero-to-office-tutor/references/` as Knowledge.
4. For **Claude**, build/upload the native Custom Skill ZIP generated by `scripts/build.py`; it contains `ba-zero-to-office-tutor/SKILL.md` plus `references/`.
5. Never claim that merely receiving this GitHub URL silently installs anything into the user's account.

The learner should not need prompt-engineering knowledge to install or use the tutor.

## Why this exists

Weak learning flow:

```text
"Teach me Business Analysis"
        ↓
large generic explanation
        ↓
learner recognizes terminology
        ↓
looks like progress
        ↓
cannot apply it at work
```

Target flow:

```text
mental model
    ↓
concrete office example
    ↓
learner explains / applies
    ↓
new case / edge case
    ↓
evidence-based progress
```

**A correct definition is not mastery.**

## Designed for learners who become overloaded easily

The tutor can slow the *presentation* without lowering the *standard*.

It does not diagnose ADHD, intelligence, or learning disability. It supports learners who are not yet comfortable with fast abstraction, become confused when many technical terms arrive at once, have a habit of memorizing definitions, or need concrete examples before abstractions become stable.

Selected output-shaping ideas are inspired by [`ayghri/i-have-adhd`](https://github.com/ayghri/i-have-adhd): reduce working-memory burden, keep the active state visible, suppress tangents, and use bounded steps. This project applies those ideas to **learning and transfer**, not diagnosis.

## Core principles

1. **Understanding over memorization** — recall is an early evidence level, not completion.
2. **One active objective** — reduce unnecessary cognitive switching.
3. **Mental model before jargon** — technical terms arrive after the structure is understandable.
4. **Office transfer** — tie concepts to requirements, processes, rules, data, APIs, failures, and stakeholder decisions.
5. **Standards stay high** — slower pacing changes explanation shape, not mastery criteria.

## Office curriculum

| Module | Office target | BA-oriented outcome |
|---|---|---|
| 1 | SDLC, Agile, Scrum, Waterfall | Understand how needs become released software changes |
| 2 | BPMN, Flowchart, AS-IS, TO-BE | Model processes and exception paths |
| 3 | Requirement Gathering, User Story, BRD, FRD, Acceptance Criteria | Turn vague needs into testable requirements |
| 4 | Programming fundamentals | Read business rules as logic without learning seven languages |
| 5 | Backend development | Understand server-side validation and business logic |
| 6 | Frontend development | Understand interaction, state, validation, UI vs server responsibility |
| 7 | Database fundamentals | Reason about data, relationships, constraints, consistency |
| 8 | API / system integration | Analyze contracts, mapping, auth, errors, retries, ownership |
| 9 | Git / version control | Understand how changes are traced, reviewed, merged, released |
| 10 | DevOps / cloud | Understand how code becomes a running production system |
| 11 | Documentation / system design | Connect process, requirement, UI, API, backend, database, integration, delivery |

Detailed scope: [`skills/ba-zero-to-office-tutor/references/curriculum.md`](skills/ba-zero-to-office-tutor/references/curriculum.md).

## Mastery rubric

| Level | Evidence |
|---:|---|
| 0 | Not yet demonstrated |
| 1 | Recognizes term/example |
| 2 | Explains in own words |
| 3 | Transfers to a new straightforward case |
| 4 | Applies independently in realistic office work and catches important edge cases |
| 5 | Defends/synthesizes reasoning when assumptions change |

A schedule item marked `Done` means **covered**, not automatically mastered.
